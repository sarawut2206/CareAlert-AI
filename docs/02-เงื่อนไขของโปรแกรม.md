# 2. เงื่อนไขของโปรแกรม (Rule Book)

เอกสารนี้คือ **กฎทุกข้อที่ระบบใช้ตัดสิน** เขียนให้ตรงกับโค้ดจริง
ถ้าแก้โค้ดต้องแก้เอกสารนี้และเพิ่มเทสต์เสมอ

ไฟล์ที่เกี่ยวข้อง:
`server/src/engine/validate.js` · `assess.js` · `lexicon.js` · `triage.js` · `sla.js`

เวอร์ชันกลไกปัจจุบัน: **`rules-1.0.0`** (บันทึกไว้ในทุกการประเมิน — เคสเก่าจะรู้เสมอว่าใช้กฎชุดไหน)

## 2.1 ขั้นที่ 2 — DISCLOSE: เงื่อนไขเปิดชุดคำถามเชิงลึก

คำนวณที่ฝั่งเซิร์ฟเวอร์เสมอ (`routes/checkin.js → followUpTriggers`)
เพื่อไม่ให้แก้ได้จากฝั่งผู้ใช้ และเพื่อให้แก้เกณฑ์ได้ที่เดียว

| ชุดคำถามที่เปิด | เงื่อนไข |
|---|---|
| `fu-mood` (อารมณ์) | `c1 ≥ 2` **หรือ** `c2 ≥ 2` **หรือ** `c3 ≥ 2` **หรือ** เช็กอินรายวัน `d1 ≤ 1` |
| `fu-bullying` (การถูกรังแก) | `c6 ≥ 1` **หรือ** เลือกแท็ก `bullying` |
| `fu-home` (เรื่องที่บ้าน) | `c8 ≥ 2` **หรือ** เลือกแท็ก `family` |
| `fu-safety` (ความปลอดภัย) | `c9 ≥ 1` **หรือ** เลือกแท็ก `safety` |

**ข้อสังเกตที่ตั้งใจ:** เกณฑ์ของ `fu-safety` ต่ำที่สุด (`≥ 1` = "บางวัน")
ยอมถามเกินดีกว่าพลาด — และหน้าจอชุดนี้แสดงสายด่วนตลอดเวลา

**ข้อจำกัดสำคัญ:** เซิร์ฟเวอร์รับเฉพาะชุดคำถามที่ตรงเงื่อนไขของตัวเองเท่านั้น
ถ้าฝั่งผู้ใช้ส่ง `followUpIds` ที่ไม่ตรงเงื่อนไข ระบบจะไม่นำมาคิด

## 2.2 ขั้นที่ 3 — VALIDATE: ตรวจคุณภาพข้อมูล (ไม่ใช่ตรวจว่าโกหก)

### ธงที่ตรวจ

| ธง | เงื่อนไข | ความหมาย |
|---|---|---|
| `MISSING_KEY_ITEMS` | ข้อใน `requiredForSufficiency` ไม่ถูกตอบ | ขาดข้อสำคัญ (เช่น `c1`, `c6`, `c9`) |
| `LOW_COMPLETENESS` | ตอบ < 70% ของข้อที่ให้คะแนน | ตอบไม่ครบ |
| `RAPID_RESPONDING` | เวลามัธยฐานต่อข้อ < 700 มิลลิวินาที และตอบ ≥ 4 ข้อ | อาจกดผ่านโดยไม่ได้อ่าน |
| `UNIFORM_RESPONDING` | เลือกค่าเดียวกันทุกข้อ (≥ 6 ข้อ) **และ** เวลาต่อข้อ < 1,200 ms | ตอบเหมือนกันหมดแบบเร่งรีบ |
| `INCONSISTENT` | คู่ข้อใน `consistencyPairs` ขัดกัน | คำตอบไม่สอดคล้อง |
| `FIRST_SUBMISSION` | ไม่มีข้อมูลครั้งก่อน | ยังไม่มี baseline ไว้เทียบ |

> **ทำไมต้องดูเวลา** — ไม่ใช่เพื่อจับผิด แต่เพื่อรู้ว่า *ข้อมูลชุดนี้เชื่อได้แค่ไหน*
> นักเรียนที่กดผ่าน 9 ข้อใน 5 วินาที ไม่ได้แปลว่าโกหก — แปลว่าเรายังไม่รู้อะไรเลยเกี่ยวกับเขา
> ซึ่งต่างจากการรู้ว่าเขาสบายดี

### คู่ข้อที่ตรวจความสอดคล้อง (เช็กอินรายสัปดาห์)

| คู่ | กฎ | เหตุผล |
|---|---|---|
| `c1` ↔ `c2` | ต่างกันได้ไม่เกิน 2 ระดับ | อารมณ์เศร้ากับความไม่สนใจสิ่งรอบตัวมักไปด้วยกัน |
| `c9` ↔ `c1` | ถ้า `c9 > 0` แต่ `c1 = 0` → ผิดปกติ | ตอบว่ามีความคิดทำร้ายตัวเอง แต่บอกว่าไม่มีอารมณ์เศร้าเลย |

### สรุประดับความเพียงพอของข้อมูล

```
INSUFFICIENT  ถ้า  ขาดข้อสำคัญ  หรือ  ตอบ < 70%  หรือ  ธงคุณภาพ ≥ 2 ธง
LIMITED       ถ้า  ตอบ < 90%   หรือ  ธงคุณภาพ = 1 ธง  หรือ  เป็นครั้งแรก
SUFFICIENT    นอกเหนือจากนั้น
```

**ข้อความที่ต้องแสดง — ห้ามเปลี่ยนเป็นคำว่า "ปกติ"**

| สถานะ | ข้อความ |
|---|---|
| `INSUFFICIENT` | "ข้อมูลยังไม่เพียงพอสำหรับการสรุป" |
| `LIMITED` | "ข้อมูลพอใช้ได้ แต่ยังมีข้อจำกัด" |
| `SUFFICIENT` | "ข้อมูลครบถ้วนพอสำหรับการพิจารณาเบื้องต้น" |

## 2.3 ขั้นที่ 4 — ASSESS: 8 มิติบริบท

ทุกข้อคำถามผูกกับ **facet** ว่ามันให้ข้อมูลมิติใด แล้วแปลงเป็นค่า 0–3

| มิติ | ที่มา | น้ำหนักในดัชนีรวม |
|---|---|---|
| ความรุนแรง (severity) | ค่าสูงสุดของข้อ facet `severity` | 24% |
| ผลกระทบต่อชีวิต (impact) | facet `impact` | 18% |
| ความถี่ (frequency) | facet `frequency` | 14% |
| ระยะเวลา (duration) | facet `duration` | 12% |
| การขาดคนช่วย (isolation) | facet `support` (กลับด้านแล้ว) | 12% |
| แนวโน้มแย่ลง (trajectory) | facet `trajectory` หรือคำนวณจากครั้งก่อน | 10% |
| ความปลอดภัย (safety) | facet `safety` + คลังคำ | 10% |
| ปัจจัยปกป้อง (protective) | `3 − isolation` | *ไม่นับในดัชนี* |

### การกลับด้าน (reverse)

ข้อที่ค่าสูง = ดี (เช่น "ฉันมีคนที่ไว้ใจ") ต้องตั้ง `reverse: true`
ระบบจะแปลงเป็นค่าความห่วงใย = `ค่าสูงสุด − ค่าที่ตอบ`

### ข้อที่ไม่คิดเป็นคะแนน (`noDomainScore`)

บางข้อมีค่าเป็นตัวเลขแต่ไม่ได้แปลว่ารุนแรงกว่า เช่น
`f_when` ("เห็นครั้งล่าสุดเมื่อไหร่") — ค่า 3 = "วันนี้" คือ *ความสด* ไม่ใช่ *ความเรื้อรัง*
ข้อเหล่านี้ต้องตั้ง `noDomainScore: true` เพื่อไม่ให้ไปโป่งมิติ `duration` ผิด ๆ

### การคำนวณแนวโน้ม

เทียบผลรวม `severity + impact + frequency` กับการประเมินครั้งก่อน:

| ส่วนต่าง | trajectory |
|---|---|
| ≥ 4 | 3 |
| ≥ 3 | 2 |
| ≥ 2 | 1 |
| น้อยกว่านั้น | 0 |

### ดัชนีความห่วงใย (Concern Index)

```
ดัชนี = Σ (มิติ ÷ 3 × น้ำหนัก) × 100  −  ส่วนลดจากปัจจัยปกป้อง
```

**ส่วนลดจากปัจจัยปกป้อง (สูงสุด 8 คะแนน) จะได้ก็ต่อเมื่อครบทั้ง 3 เงื่อนไข:**

1. มิติความปลอดภัย = 0
2. มิติความรุนแรง ≤ 1
3. ไม่พบคำใด ๆ ในคลังคำ

> **ดัชนีนี้ใช้จัดลำดับคิวเท่านั้น ไม่ใช่คะแนนของนักเรียน และไม่ใช่ตัวตัดสินระดับ**

## 2.4 คลังคำสัญญาณความปลอดภัย

หน้าที่เดียว: **ทำให้มนุษย์ได้อ่านข้อความนั้นเร็วขึ้น**

| หมวด | ความรุนแรง | ผลต่อมิติความปลอดภัย |
|---|---|---|
| `SUICIDE_INTENT` ความคิดจบชีวิต | CRITICAL | ยกเป็น 3 |
| `SELF_HARM` การทำร้ายตนเอง | CRITICAL | ยกเป็น 3 |
| `VIOLENCE_THREAT` จะทำร้ายผู้อื่น | CRITICAL | ยกเป็น 3 |
| `ABUSE` ถูกกระทำ/ล่วงละเมิด | CRITICAL | ยกเป็น 3 |
| `WEAPON` อาวุธ | HIGH | ยกเป็น 2 |
| `RUNAWAY` หนีออกจากบ้าน | HIGH | ยกเป็น 2 |
| `SUBSTANCE` สารเสพติด | HIGH | ยกเป็น 2 |
| `HELP_SEEKING` ขอความช่วยเหลือตรง ๆ | HIGH | ยกเป็น 2 |
| `BULLYING` ถูกรังแก | MODERATE | — |
| `DISTRESS` ความทุกข์ทั่วไป | MODERATE | — |

### การจัดการบริบท (negation / third-party)

| สถานการณ์ | ผล |
|---|---|
| มีคำปฏิเสธติดหน้าคำพอดี (`ไม่`, `เลิก`, `หยุด`) | ความเชื่อมั่น = ต่ำ **แต่ยังส่งให้มนุษย์อ่าน** |
| มีวลีปฏิเสธในช่วง 12 ตัวอักษรก่อนหน้า (`ไม่เคย`, `ไม่ได้`, `ไม่คิดจะ`) | ความเชื่อมั่น = ต่ำ |
| ทั้งข้อความมีวลีอ้างถึงผู้อื่น (`เพื่อนบอกว่า`, `ในข่าว`) | ความเชื่อมั่น = กลาง |

> **ระบบไม่เคยตัดคำที่ตรวจพบทิ้งเอง** เพราะ "ไม่อยากตายหรอก แค่เหนื่อยมาก"
> ก็ยังเป็นประโยคที่ครูควรได้อ่าน — ระบบแค่ติดป้ายว่าต้องอ่านเองก่อนสรุป

## 2.5 ขั้นที่ 5 — ALERT: กฎตัดสินระดับ

**วิธีตัดสิน:** ประเมิน *ทุกกฎ* แล้วใช้ **ระดับสูงสุด** ที่ตรงเงื่อนไข
(ไม่ใช่หยุดที่กฎแรก) เพื่อให้เห็นเหตุผลครบทุกข้อในเอกสารเคส

### ระดับ 4 — Immediate Safety Review (ตรวจสอบความปลอดภัยทันที)

| รหัสกฎ | เงื่อนไข |
|---|---|
| `L4.SAFETY_NOW` | คำตอบด้านความปลอดภัย = 3 (เช่น "ตอนนี้ฉันไม่ปลอดภัย" / `c9` = เกือบทุกวัน) |
| `L4.SAFETY_PLAN` | `s_plan ≥ 3` (คิดวิธีไว้ชัดเจน) **หรือ** `s_past ≥ 3` (เคยลงมือภายในเดือนนี้) |
| `L4.LEXICON_CRITICAL` | พบคำหมวด CRITICAL ในข้อความอิสระ |
| `L4.FRIEND_IMMINENT` | เพื่อนแจ้งว่า "คิดว่าไม่ปลอดภัย ต้องช่วยด่วน" (`f_safe = 3`) |
| `L4.FRIEND_LETHAL_SIGNS` | เพื่อนเห็นสัญญาณเร่งด่วนภายในสัปดาห์นี้ (`f_when ≥ 2`) และมีแท็ก พูดถึงการตาย / ร่องรอยทำร้ายตัวเอง / แจกของ / ขู่ทำร้ายผู้อื่น / อาวุธ |
| `L4.STAFF_SAFETY` | บุคลากรระบุว่ามีข้อกังวลความปลอดภัยชัดเจน (`n_safety = 3`) |
| `L4.HOME_UNSAFE` | `h_safe ≥ 3` **หรือ** (`h_safe ≥ 2` และมีแท็กความรุนแรงในบ้าน) |

**หมายเหตุการออกแบบ:** `L4.SAFETY_NOW` ใช้ค่าจาก *คำตอบ* เท่านั้น ไม่ใช่ค่าที่ถูกยกขึ้นจากคลังคำ
เพื่อไม่ให้เหตุผลที่แสดงต่อครูคลาดเคลื่อนจากสิ่งที่นักเรียนตอบจริง
(กรณีคลังคำมีกฎ `L4.LEXICON_CRITICAL` แยกอยู่แล้ว)

### ระดับ 3 — Priority Intervention (ต้องช่วยเหลือโดยเร็ว)

| รหัสกฎ | เงื่อนไข |
|---|---|
| `L3.SAFETY_SIGNAL` | มิติความปลอดภัย = 2 หรือคำตอบด้านความปลอดภัย ≥ 2 |
| `L3.LEXICON_HIGH` | พบคำหมวด HIGH |
| `L3.BULLYING_ONGOING` | ถูกรังแก ≥ 2 **และ** ความถี่ ≥ 2 **และ** ผลกระทบ ≥ 2 |
| `L3.HIGH_INDEX` | ดัชนีความห่วงใย ≥ 65 |
| `L3.MULTI_DOMAIN_CHRONIC` | มีสัญญาณ ≥ 2 ด้าน **และ** ระยะเวลา ≥ 2 |
| `L3.PERSISTENT` | พบสัญญาณต่อเนื่อง ≥ 3 ครั้งติดกัน |
| `L3.EXPLICIT_HELP` | ขอให้ติดต่อกลับ **และ** มีความทุกข์/สัญญาณความปลอดภัย/คำในคลังคำ |
| `L3.ISOLATION` | ไม่มีใครให้พึ่งเลย (3) **และ** ความรุนแรง ≥ 2 |
| `L3.ESCALATING` | แนวโน้มแย่ลงอย่างชัดเจน (3) |

### ระดับ 2 — Review (ให้ผู้รับผิดชอบตรวจสอบ)

| รหัสกฎ | เงื่อนไข |
|---|---|
| `L2.MODERATE_INDEX` | ดัชนี ≥ 35 |
| `L2.SINGLE_DOMAIN` | พบสัญญาณชัดเจนอย่างน้อยหนึ่งด้าน |
| `L2.INSUFFICIENT_WITH_SIGNAL` | ข้อมูลไม่เพียงพอ **แต่** มีสัญญาณบางอย่าง |
| `L2.TREND_WORSENING` | แนวโน้มแย่ลง ≥ 2 |
| `L2.STAFF_NOTE` | **ทุก** บันทึกของบุคลากร |
| `L2.FRIEND_REPORT` | **ทุก** การแจ้งเป็นห่วงเพื่อน |
| `L2.WANTS_CONTACT` | นักเรียนอยากให้ติดต่อกลับ |
| `L2.LEXICON_MODERATE` | พบคำหมวด MODERATE |
| `L2.CONSECUTIVE` | พบสัญญาณต่อเนื่อง 2 ครั้งติดกัน |
| `L2.SELF_DISCLOSURE` | **ทุก** การเล่าเรื่องของตัวเอง |

> `L2.STAFF_NOTE` และ `L2.FRIEND_REPORT` เป็นกฎแบบ "ทุกครั้ง" โดยตั้งใจ —
> ถ้ามีคนอุตส่าห์มาบอก แปลว่ามีคนคิดว่ามันสำคัญพอ ต้องมีมนุษย์ดูเสมอ

### ระดับ 1 — Support

ไม่มีกฎใดตรงเงื่อนไข → ไม่เปิดเคส นักเรียนได้กิจกรรมชั้นที่ 1 ตามปกติ

**กรณีพิเศษ `L1-U`:** ระดับ 1 แต่ข้อมูลไม่เพียงพอ
→ **ห้ามบันทึกว่า "ไม่พบปัญหา"** ต้องชวนเช็กอินซ้ำ

### ตัวปรับ (Modifiers) — บันทึกไว้ แต่ไม่เปลี่ยนระดับ

| รหัส | เงื่อนไข | สิ่งที่ต้องทำ |
|---|---|---|
| `MOD.PROTECTIVE` | ปัจจัยปกป้อง ≥ 2 | ใช้เป็นจุดแข็งในการวางแผน — **ห้ามใช้ลดระดับ** |
| `MOD.INSUFFICIENT_DATA` | ข้อมูลไม่เพียงพอ | ห้ามบันทึกว่า "ไม่พบปัญหา" |
| `MOD.LOW_CONFIDENCE_TEXT` | คำที่พบอาจเป็นการปฏิเสธ/พูดถึงผู้อื่น | ต้องอ่านข้อความจริงก่อนสรุป |
| `MOD.RETALIATION_RISK` | `b_retaliation ≥ 2` | ต้องวางแผนคุ้มครองก่อนดำเนินการกับผู้กระทำ |
| `MOD.NOT_READY` | นักเรียนยังไม่พร้อมให้ติดต่อ | ยังต้องติดต่อตามระดับ แต่เริ่มด้วยการสร้างความไว้วางใจ |

## 2.6 ตัวช่วยภาษา (LLM) — ปิดโดยค่าเริ่มต้น

เปิดได้ที่ `server/.env` เท่านั้น (`LLM_ENABLED=true` + `ANTHROPIC_API_KEY`)
**จงใจไม่ให้เปิดจากหน้าเว็บ** เพื่อไม่ให้เปิดใช้โดยไม่ตั้งใจ

| อนุญาต | ห้ามเด็ดขาด |
|---|---|
| สรุปข้อความอิสระเป็นข้อเท็จจริงสั้น ๆ ให้ครูอ่านเร็วขึ้น | วินิจฉัยโรค |
| ชี้ว่าอาจมีสัญญาณที่คลังคำจับไม่ได้ (เช่น การเปรียบเปรย) | ทำนายพฤติกรรม |
| **ยกระดับขึ้น** เมื่อเห็นสิ่งที่กฎมองข้าม | **ลดระดับ** ที่กฎกำหนดไว้ |

```
ระดับสุดท้าย = max(ระดับจากกฎ, ระดับที่ LLM เสนอ)
```

ถ้าเรียก API ไม่สำเร็จ ระบบทำงานต่อด้วยกฎตามปกติ (fail-open ไปที่กฎ)
และทุกครั้งที่ LLM ยกระดับ จะบันทึกกฎ `LLM.RAISED` พร้อมข้อความสรุปไว้ในเคส

## 2.7 ขั้นที่ 6 — INTERVENE: กำหนดเวลา (SLA)

| ระดับ | ต้องรับเรื่องภายใน | ต้องติดต่อนักเรียนภายใน | ผู้รับผิดชอบ | ต้องมีผู้ใหญ่ 2 คน |
|---|---|---|---|---|
| 4 | 30 นาที | **60 นาที (นาฬิกาจริง)** | ครูแนะแนว + ผู้บริหารรับทราบ | ✅ |
| 3 | 4 ชั่วโมงเรียน (240 นาที) | 1 วันเรียน (480 นาที ≈ ภายในวันเรียนถัดไป) | ครูแนะแนว + ครูที่ปรึกษา | — |
| 2 | 1 วันเรียน (480 นาที) | 3 วันเรียน (1,440 นาที) | ครูที่ปรึกษา | — |
| 1 | — | — | ระบบทั่วไป | — |

> หน่วยของระดับ 2–3 คือ "นาทีของเวลาเรียน" — 1 วันเรียน = 480 นาที (08:00–16:00)

**ระดับ 4 ใช้เวลานาฬิกาจริง** ไม่ข้ามวันหยุดหรือนอกเวลาเรียน — ความปลอดภัยรอไม่ได้
ระดับ 2–3 นับเฉพาะเวลาเรียน (จันทร์–ศุกร์ 08:00–16:00 ปรับได้ใน `.env`)
เพื่อให้ SLA เป็นสิ่งที่ทำได้จริง ไม่ใช่ตัวเลขที่เกินกำหนดตั้งแต่วันเสาร์

### ขั้นตอนบังคับสำหรับระดับ 4

1. ตรวจสอบว่านักเรียนอยู่ที่ไหน และอยู่กับใครในขณะนี้
2. พบนักเรียนในที่ปลอดภัย โดยมีผู้ใหญ่รับรู้อย่างน้อย 2 คน
3. ประเมินความปลอดภัยเฉพาะหน้า
4. **อย่าปล่อยให้นักเรียนอยู่คนเดียวจนกว่าจะยืนยันความปลอดภัย**
5. ติดต่อผู้ปกครอง **เว้นแต่ผู้ปกครองคือแหล่งที่มาของอันตราย**
6. ประสาน 1323 / 1669 เมื่อจำเป็น
7. บันทึกทุกขั้นตอนพร้อมเวลา

### ขั้นตอนเพิ่มเติมอัตโนมัติ

| เมื่อพบ | ระบบเพิ่มขั้นตอน |
|---|---|
| `b_retaliation ≥ 2` | วางแผนคุ้มครองจากการถูกเอาคืน **ก่อน** ดำเนินการกับผู้กระทำ |
| แท็กความรุนแรงในบ้าน หรือคลังคำหมวด `ABUSE` | พิจารณาแนวปฏิบัติคุ้มครองเด็กและการแจ้งตามกฎหมาย (1300) |
| คลังคำหมวด `SUBSTANCE` | ประสานงานด้านสารเสพติด **โดยเน้นช่วยเหลือ ไม่ใช่ลงโทษ** |
| ข้อมูลไม่เพียงพอ | ยืนยันด้วยการพูดคุยโดยตรงก่อนสรุปใด ๆ |

## 2.8 ขั้นที่ 7 — FOLLOW-UP และเงื่อนไขการปิดเคส

### เคสหนึ่งนักเรียนหนึ่งเคส

นักเรียนหนึ่งคนมีเคสที่เปิดอยู่ได้ครั้งละหนึ่งเคส ข้อมูลใหม่จะเข้าไปเพิ่มในเคสเดิม
เพื่อไม่ให้ครูเห็นเคสซ้ำซ้อนจนหาของจริงไม่เจอ

- ข้อมูลใหม่ที่รุนแรงกว่า → **ยกระดับอัตโนมัติ** + บันทึกเหตุการณ์ `escalate`
- ข้อมูลใหม่ที่ไม่รุนแรงกว่า → บันทึกเป็น `note` ในเคสเดิม
- **ระบบไม่ลดระดับให้เอง** การลดระดับต้องเป็นการตัดสินใจของมนุษย์และถูกบันทึกไว้

### ปิดเคสไม่ได้จนกว่าจะครบ

| เงื่อนไข | ตรวจจาก |
|---|---|
| บันทึกว่าได้พูดคุยกับนักเรียนแล้ว | `first_contact_at` |
| ยืนยันความปลอดภัยของนักเรียน | `safety_confirmed` |
| มีบันทึกการดำเนินการหรือการส่งต่ออย่างน้อย 1 รายการ | `case_events` ประเภท `action` / `referral` |
| ถ้าเคยเป็นระดับ 4 → ระบุผลการแจ้งผู้ปกครองหรือเหตุผลที่ไม่แจ้ง | `guardian_informed` |

**การข้ามเงื่อนไข (override)** ทำได้เฉพาะครูแนะแนวหรือผู้ดูแลระบบ
และถูกบันทึกไว้ในเคสว่าข้ามอะไรไปบ้าง
**เคสที่เคยเป็นระดับ 4 ต้องปิดโดยครูแนะแนวขึ้นไปเท่านั้น**

### รอบการติดตาม

| ระดับ | นัดติดตามที่ (วัน) |
|---|---|
| 4 | 1 · 3 · 7 · 30 |
| 3 | 3 · 7 · 30 |
| 2 | 7 · 30 |

## 2.9 สิ่งที่นักเรียนเห็นและไม่เห็น

| นักเรียนเห็น | นักเรียนไม่เห็น |
|---|---|
| ข้อความอบอุ่นที่เหมาะกับสถานการณ์ | ระดับ (1–4) |
| สายด่วน (เมื่อระดับ ≥ 3) | ดัชนีความห่วงใย |
| หน้าจอวิกฤตพร้อมขั้นตอนทำทันที (ระดับ 4) | ชื่อกฎที่ทำงาน |
| กิจกรรมทักษะชีวิตที่แนะนำ | สถานะเคส |
| รหัสอ้างอิง (กรณีแจ้งแบบไม่ระบุตัวตน) | ว่าใครเป็นผู้รับผิดชอบเคส |

**เหตุผล:** ถ้านักเรียนเห็นคะแนน เขาจะเรียนรู้ที่จะตอบให้ได้คะแนนที่ต้องการ
และบางคนจะรู้สึกว่าตัวเองถูกจัดประเภท ซึ่งทำลายทั้งข้อมูลและความไว้วางใจ

## 2.10 กรณีนักเรียนเลือกไม่เปิดเผยชื่อ

| สถานการณ์ | ระบบทำอย่างไร |
|---|---|
| เล่าเรื่องตัวเอง แบบไม่บอกชื่อ **และ** ระดับ < 4 | เคสไม่ผูกกับตัวตน ครูเห็นแค่เนื้อหา |
| เล่าเรื่องตัวเอง แบบไม่บอกชื่อ **และ** ระดับ = 4 | **ผูกตัวตน** และแจ้งนักเรียนตรง ๆ ทันทีบนหน้าจอ |
| เป็นห่วงเพื่อน แบบไม่บอกชื่อผู้แจ้ง | ไม่บันทึกผู้แจ้งเลย + ให้รหัสอ้างอิงไว้ติดตาม |

**เงื่อนไขนี้ถูกบอกไว้ล่วงหน้าเสมอ** ทั้งในเอกสารความยินยอมและบนหน้าจอก่อนเริ่มเล่า
— ไม่มีการแอบทำ เพราะการทรยศความลับโดยไม่บอกก่อนจะทำลายระบบทั้งระบบ
