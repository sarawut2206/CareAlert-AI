# 3. โครงสร้างข้อมูลและ API

## 3.1 ตารางฐานข้อมูล

ไฟล์: `server/src/schema.sql` · ฐานข้อมูล: `server/data/carealert.db`

### กลุ่มผู้ใช้และโครงสร้างโรงเรียน

| ตาราง | เก็บอะไร | หมายเหตุ |
|---|---|---|
| `users` | บัญชีทุกบทบาท | รหัสผ่าน scrypt · ล็อกอัตโนมัติเมื่อผิด 8 ครั้ง |
| `classrooms` | ห้องเรียนและครูที่ปรึกษา | ใช้กำหนดขอบเขตสิทธิ์ของครูที่ปรึกษา |
| `students` | ข้อมูลนักเรียน | เก็บเท่าที่จำเป็นต่อการติดต่อและช่วยเหลือ |
| `consents` | ความยินยอมตามเวอร์ชัน | ถอนได้ (`withdrawn_at`) |

### กลุ่มข้อมูลที่นักเรียนให้มา (แยกจากการประเมินของระบบเสมอ)

| ตาราง | เก็บอะไร |
|---|---|
| `checkins` | คำตอบดิบ + เวลาที่ใช้ต่อข้อ + ระยะเวลารวม |
| `reports` | การเล่าเรื่องตัวเอง / เป็นห่วงเพื่อน / บันทึกของบุคลากร |
| `lifeskill_progress` | ความคืบหน้าและข้อความสะท้อนตัวเอง |

> **แยกกันสำคัญมาก** — ถ้าวันหนึ่งพบว่ากฎประเมินผิด เราต้องประเมินข้อมูลเดิมใหม่ได้
> โดยไม่สูญเสียสิ่งที่นักเรียนพูดจริง

### กลุ่มผลการประเมินและเคส

| ตาราง | เก็บอะไร | คอลัมน์สำคัญ |
|---|---|---|
| `assessments` | ผลประเมินแต่ละครั้ง | `engine_version` · `rationale_json` (กฎที่ทำงาน) · `dimensions_json` |
| `cases` | เคสที่เปิด | `level` · `peak_level` · SLA · `safety_confirmed` · `close_reason` |
| `case_links` | เชื่อมเคสกับผลประเมินหลายครั้ง | |
| `case_events` | ทุกการกระทำในเคส | ประเภท: opened / acknowledged / contacted / action / referral / escalate / followup / closed / reopened / note |

**`peak_level` แยกจาก `level`** เพื่อให้รู้ว่าเคสนี้ *เคย* รุนแรงถึงระดับใด
ใช้บังคับว่าเคสที่เคยเป็นระดับ 4 ต้องปิดโดยครูแนะแนวขึ้นไป
แม้ปัจจุบันจะถูกลดระดับลงมาแล้วก็ตาม

### กลุ่มระบบ

| ตาราง | เก็บอะไร |
|---|---|
| `audit_log` | ใครเข้าถึงข้อมูลอะไรเมื่อไหร่ จาก IP ใด — **รวมถึงการเปิดดูเฉย ๆ** |
| `settings` | ชื่อโรงเรียน ช่องทางติดต่อ webhook ข้อความความยินยอม |

## 3.2 API

ทุกเส้นทางขึ้นต้นด้วย `/api` · ยืนยันตัวตนด้วย `Authorization: Bearer <token>`

### สาธารณะ (ไม่ต้องล็อกอิน)

| Method | เส้นทาง | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/health` | ตรวจว่าเซิร์ฟเวอร์ทำงาน |
| GET | `/api/meta/help` | **สายด่วนและช่องทางช่วยเหลือ** |
| GET | `/api/meta/consent` | ข้อความความยินยอม |
| POST | `/api/auth/login` | เข้าสู่ระบบ |

> `/api/meta/help` เปิดสาธารณะโดยตั้งใจ — นักเรียนที่ลืมรหัสผ่านตอนตีสองก็ยังต้องหาเบอร์สายด่วนได้

### นักเรียน

| Method | เส้นทาง | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/checkin/templates?cadence=daily\|weekly` | ดึงชุดคำถาม |
| POST | `/api/checkin/follow-ups` | ถามว่าคำตอบนี้ควรเปิดคำถามเชิงลึกชุดไหน |
| POST | `/api/checkin/submit` | ส่งเช็กอิน |
| GET | `/api/checkin/mine` | ประวัติเช็กอินของตัวเอง |
| GET | `/api/reports/templates` | ชุดคำถามการแจ้งเรื่อง |
| POST | `/api/reports/self` | เล่าเรื่องของตัวเอง |
| POST | `/api/reports/friend` | เป็นห่วงเพื่อน |
| GET | `/api/lifeskills` · `/api/lifeskills/:id` | กิจกรรมทักษะชีวิต |
| POST | `/api/lifeskills/:id/progress` · `/reflection` | บันทึกความคืบหน้า / ข้อความสะท้อน |

### บุคลากร

| Method | เส้นทาง | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/cases?status=open&level=4` | คิวเคส |
| GET | `/api/cases/summary` | ตัวเลขสรุปด้านบน |
| GET | `/api/cases/:id` | รายละเอียดเคส + เหตุผล + ข้อความต้นฉบับ |
| POST | `/api/cases/:id/acknowledge` | รับเรื่อง |
| POST | `/api/cases/:id/contact` | บันทึกการพูดคุย (+ ยืนยันความปลอดภัย) |
| POST | `/api/cases/:id/action` | บันทึกการดำเนินการ |
| POST | `/api/cases/:id/referral` | ส่งต่อ |
| POST | `/api/cases/:id/guardian` | บันทึกการแจ้งผู้ปกครอง |
| POST | `/api/cases/:id/followup` | บันทึกการติดตาม + นัดครั้งถัดไป |
| POST | `/api/cases/:id/level` | เปลี่ยนระดับ (ลดระดับต้องเป็นครูแนะแนวขึ้นไป) |
| POST | `/api/cases/:id/close` · `/reopen` | ปิด / เปิดเคสใหม่ |
| GET | `/api/students?q=&classroomId=` | ค้นหานักเรียน (ถูกบันทึก audit) |
| GET | `/api/students/:id` | ประวัติการดูแล |
| POST | `/api/reports/staff-note` | บันทึกข้อสังเกต |
| GET | `/api/analytics/overview?days=30` | ภาพรวม (ข้อมูลรวมเท่านั้น) |
| GET | `/api/meta/engine` | **กฎทั้งหมดของระบบ** |

### ผู้ดูแลระบบ

| Method | เส้นทาง | ใช้ทำอะไร |
|---|---|---|
| GET/POST | `/api/admin/users` | จัดการบัญชีบุคลากร |
| POST | `/api/admin/users/:id/reset-password` | ตั้งรหัสผ่านใหม่ |
| POST | `/api/admin/students/import` | นำเข้ารายชื่อจาก CSV |
| POST/PUT | `/api/admin/classrooms` | จัดการห้องเรียน |
| GET/PUT | `/api/admin/settings` | ตั้งค่าโรงเรียน |
| GET | `/api/admin/audit` | ร่องรอยการใช้งาน |
| POST | `/api/admin/retention/purge` | ลบข้อมูลที่พ้นระยะเก็บ (มี dry-run) |

### เครื่องมือสำหรับตรวจสอบ

| Method | เส้นทาง | ใช้ทำอะไร |
|---|---|---|
| POST | `/api/checkin/dry-run` | ทดลองกลไกประเมินโดย**ไม่บันทึกลงฐานข้อมูล** |

ใช้ตอนอบรมครู หรือตอนตรวจสอบว่ากฎทำงานตามที่เข้าใจ
(เฉพาะครูแนะแนวและผู้ดูแลระบบ)

## 3.3 การเพิ่มชุดคำถามใหม่

แก้ไฟล์เดียว: `server/src/content/templates.js`

```js
export const myTemplate = {
  id: 'my-template',
  version: '1.0.0',
  title: 'ชื่อที่นักเรียนเห็น',
  intro: 'คำอธิบายสั้น ๆ',
  items: [
    {
      id: 'q1',
      text: 'คำถาม',
      type: 'scale',            // scale | choice | multi | text
      options: FREQ4,
      domain: 'mood',           // ใช้จัดกลุ่มและแสดงเหตุผลเป็นภาษาไทย
      facet: 'severity',        // มิติที่ข้อนี้ให้ข้อมูล
      weight: 1.0,
      reverse: false,           // true ถ้าค่าสูง = ดี
      critical: false,          // true ถ้าเป็นข้อความปลอดภัย
      noDomainScore: false,     // true ถ้าตัวเลขไม่ได้แปลว่ารุนแรงกว่า
      required: true,
    },
  ],
  consistencyPairs: [],
  requiredForSufficiency: ['q1'],
};
```

จากนั้นเพิ่มลงใน `templates` ท้ายไฟล์ — ไม่ต้องแก้ฐานข้อมูลหรือกลไกประเมิน

### ถ้าโรงเรียนได้รับอนุญาตให้ใช้เครื่องมือมาตรฐานฉบับจริง

เพิ่มเป็น template แยก และตั้ง `licensedInstrument: true` พร้อมระบุที่มา
**อย่านำข้อจากเครื่องมือที่มีลิขสิทธิ์มาผสมกับข้อที่เขียนเอง** เพราะจะทำให้
ค่าความเที่ยง/ความตรงที่รายงานไว้ในงานวิจัยต้นทางใช้อ้างไม่ได้อีกต่อไป
