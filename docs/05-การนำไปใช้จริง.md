# 5. การติดตั้งและการนำไปใช้จริง

## 5.1 ติดตั้ง

### ความต้องการขั้นต่ำ

- Node.js **22.5 ขึ้นไป** (แนะนำ 24) — ดาวน์โหลดจาก [nodejs.org](https://nodejs.org)
- พื้นที่ว่าง ~200 MB
- **ไม่ต้องติดตั้งฐานข้อมูลแยก ไม่ต้องมี build tools**

### ขั้นตอน

```bash
npm run setup
```

```bash
npm run build
```

```bash
npm start
```

เปิดที่ `http://localhost:8787`

### ตั้งค่าก่อนใช้งานจริง

สร้างไฟล์ `server/.env`:

```
PORT=8787
NODE_ENV=production

# ต้องตั้งเอง มิฉะนั้นผู้ใช้จะหลุดออกจากระบบทุกครั้งที่ restart
JWT_SECRET=<สุ่มอักขระยาว ๆ อย่างน้อย 32 ตัว>
JWT_TTL=28800

# เวลาเรียนของโรงเรียน (ใช้คำนวณ SLA ระดับ 2-3)
SCHOOL_START_HOUR=8
SCHOOL_END_HOUR=16

# ระยะเวลาเก็บข้อมูล (วัน)
RETENTION_CHECKIN_DAYS=365
RETENTION_CASE_DAYS=1095
RETENTION_AUDIT_DAYS=1095

# ตัวช่วยภาษา — ปิดไว้ก่อนจนกว่าจะผ่านการพิจารณาของโรงเรียน
LLM_ENABLED=false
# ANTHROPIC_API_KEY=sk-ant-...
# LLM_MODEL=claude-sonnet-5
```

สร้าง `JWT_SECRET` ได้ด้วย:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### สำรองข้อมูล

คัดลอกไฟล์เดียว: `server/data/carealert.db`

ตัวอย่างงานสำรองรายวัน (Windows Task Scheduler):

```bash
copy "server\data\carealert.db" "D:\backup\carealert-%date:~10,4%%date:~4,2%%date:~7,2%.db"
```

> เก็บสำเนาไว้คนละเครื่องกับเซิร์ฟเวอร์ และเข้ารหัสไดรฟ์ที่เก็บสำเนา

## 5.2 เตรียมข้อมูลโรงเรียน

### ลำดับที่แนะนำ

1. **เข้าสู่ระบบด้วย `admin`** → เปลี่ยนรหัสผ่านทันที
2. **สร้างบัญชีบุคลากร** (เมนูผู้ดูแลระบบ → บุคลากร)
   - อย่างน้อยต้องมีครูแนะแนว 1 คน เพราะเป็นผู้รับผิดชอบเคสระดับ 3–4 โดยอัตโนมัติ
3. **สร้างห้องเรียนและกำหนดครูที่ปรึกษา** — สิทธิ์การเห็นข้อมูลผูกกับข้อนี้
4. **นำเข้ารายชื่อนักเรียน** — ทำได้ 2 วิธี

   **ก. วางข้อความ CSV ในหน้าผู้ดูแลระบบ** (เหมาะกับจำนวนน้อย)
   ```
   30101,เด็กชายตัวอย่าง หนึ่ง,ม.3/1,2554
   30102,เด็กหญิงตัวอย่าง สอง,ม.3/1,2554
   ```

   **ข. นำเข้าจากไฟล์ Excel ของทะเบียนโดยตรง** (เหมาะกับทั้งระดับชั้น)
   ```bash
   node scripts/import-roster.mjs "ม.4.xls" --level ม.4
   ```
   สคริปต์รองรับไฟล์ `.xls` รุ่นเก่าที่เข้ารหัสภาษาไทยแบบ TIS-620 (ต้องมี `pip install xlrd`)
   เติมคำนำหน้าห้องให้อัตโนมัติ (คอลัมน์ `room` = `1` → `ม.4/1`) และสร้างห้องเรียนที่ยังไม่มีให้เอง
   ใส่ `--dry-run` เพื่อดูผลก่อนนำเข้าจริง

   ทั้งสองวิธีระบบสร้าง PIN 6 หลักให้อัตโนมัติ — **เก็บครั้งเดียว ระบบไม่แสดงซ้ำ**
   วิธี ข. จะบันทึกเป็นไฟล์ `รหัสผ่านนักเรียน-<ระดับชั้น>.txt` แยกตามห้องไว้ให้พร้อมพิมพ์

   > ไฟล์รายชื่อจริงและไฟล์รหัสผ่านอยู่ใน `.gitignore` แล้ว — **ห้าม commit ขึ้น git**
5. **ตั้งค่าโรงเรียน** → ชื่อโรงเรียน และช่องทางติดต่อในโรงเรียน
   (ปรากฏในหน้าขอความช่วยเหลือของนักเรียน)
6. **ตรวจสอบเบอร์สายด่วน** ใน `server/src/content/help.js` ให้เป็นปัจจุบัน

### การส่งมอบ PIN ให้นักเรียนอย่างปลอดภัย

- ตัดเป็นชิ้นแยกรายคน อย่าแจกทั้งแผ่น
- อย่าส่งในกลุ่มไลน์ห้อง
- แจ้งนักเรียนว่าเปลี่ยนรหัสผ่านได้ และไม่ควรบอกใคร

## 5.3 สิ่งที่ต้องทำก่อนเปิดใช้กับนักเรียน (ทำระบบอย่างเดียวไม่พอ)

> **ระบบนี้จะล้มเหลวถ้าโรงเรียนไม่ได้เตรียมคน** เพราะเมื่อนักเรียนกล้าบอกแล้ว
> แต่ไม่มีใครมารับ ความไว้วางใจจะหายไปและไม่กลับมาอีก

### รายการที่ต้องเสร็จก่อน

- [ ] **มีผู้รับผิดชอบชัดเจน** ว่าใครดูคิวเคสทุกวัน และใครดูแทนเมื่อคนนั้นลา
- [ ] **แนวปฏิบัติเมื่อเจอเคสระดับ 4** เขียนเป็นเอกสาร ผ่านความเห็นชอบผู้บริหาร
- [ ] **รายชื่อหน่วยงานส่งต่อ** พร้อมเบอร์และชื่อผู้ประสาน (รพ.สต. / รพ.ชุมชน / รพ.จิตเวชเด็ก / บ้านพักเด็กและครอบครัว)
- [ ] **อบรมครูอย่างน้อย 1 ครั้ง** เรื่องการฟังเชิงลึก การถามเรื่องความปลอดภัย และสิ่งที่ห้ามพูด
- [ ] **แจ้งผู้ปกครอง** ว่าระบบนี้คืออะไร ทำอะไร และไม่ทำอะไร
- [ ] **แนวปฏิบัติกรณีผู้ปกครองคือแหล่งที่มาของอันตราย** (ห้ามโทรแจ้งโดยอัตโนมัติ)
- [ ] **ทดลองซ้อมหนึ่งเคสสมมติ** ตั้งแต่นักเรียนส่งจนปิดเคส จับเวลาจริง

### สิ่งที่ต้องบอกนักเรียนในวันเปิดใช้

1. ระบบนี้คืออะไร และ**ไม่ใช่**อะไร
2. ใครอ่านได้บ้าง (ไม่ใช่ครูทุกคน)
3. ข้อยกเว้นเรื่องความลับ — พูดตรง ๆ ไม่ต้องอ้อม
4. ถ้าไม่อยากบอกชื่อก็ได้
5. ปุ่มขอความช่วยเหลือใช้ได้ตลอด แม้ไม่ล็อกอิน
6. **การบอกครูเพราะเป็นห่วงเพื่อน ไม่ใช่การฟ้อง**

## 5.4 จังหวะการใช้งานที่แนะนำ

| ความถี่ | กิจกรรม | ใครทำ |
|---|---|---|
| ทุกวัน | ดูคิวเคส เช็กว่ามีระดับ 3–4 ค้างไหม | ครูแนะแนว |
| ทุกวัน (ไม่บังคับ) | เช็กอินรายวัน 30 วินาที ในคาบโฮมรูม | นักเรียน |
| ทุกสัปดาห์ | เช็กอินรายสัปดาห์ | นักเรียน |
| ทุกสัปดาห์ | ทบทวนเคสที่เกินกำหนด | ครูแนะแนว + ครูที่ปรึกษา |
| ทุกเดือน | กิจกรรมทักษะชีวิต 1–2 โมดูล | ครูที่ปรึกษา |
| ทุกภาคเรียน | สุ่มตรวจ audit log · ทบทวนเกณฑ์ · สำรวจความไว้วางใจของนักเรียน | ผู้ดูแล + ทีมระบบดูแล |

**อย่าบังคับให้เช็กอินทุกวันตั้งแต่แรก** — เริ่มที่รายสัปดาห์ก่อน
การบังคับมากเกินไปทำให้เกิดการตอบแบบกดผ่าน ซึ่งทำให้ข้อมูลไร้ค่าและระบบเตือนพลาด

## 5.5 แผนนำร่อง 12 สัปดาห์

| ช่วง | สิ่งที่ทำ | ตัวชี้วัดที่ดู |
|---|---|---|
| **สัปดาห์ 0** | เตรียมคน แนวปฏิบัติ รายชื่อส่งต่อ ซ้อมเคสสมมติ | รายการเช็กลิสต์ครบ |
| **สัปดาห์ 1–2** | นำร่อง 2 ห้อง (~60–80 คน) | อัตราการเช็กอิน · เวลาที่ใช้ตอบ |
| **สัปดาห์ 3–4** | ทบทวนเกณฑ์กับครูแนะแนว | สัดส่วนเคสที่ครูเห็นว่า "ไม่จำเป็น" |
| **สัปดาห์ 5–8** | ขยายเป็นระดับชั้น | เวลารับเรื่อง · เวลาติดต่อ · เคสค้าง |
| **สัปดาห์ 9–12** | ประเมินผลและตัดสินใจขยาย | ครบทุกตัวชี้วัดด้านล่าง |

### ตัวชี้วัดที่ควรใช้จริง

**ตัวชี้วัดที่ดี** (วัดว่าระบบช่วยได้จริงไหม)

| ตัวชี้วัด | เป้าหมายเริ่มต้น |
|---|---|
| เคสระดับ 4 ที่ติดต่อนักเรียนได้ภายใน 1 ชั่วโมง | ≥ 95% |
| เคสระดับ 3 ที่ติดต่อได้ภายใน 24 ชั่วโมงเรียน | ≥ 90% |
| เคสที่ปิดโดยครบเงื่อนไข (ไม่ใช้ override) | ≥ 80% |
| สัดส่วนเรื่องที่มาจากช่องทาง "เล่าเอง" และ "เป็นห่วงเพื่อน" | ≥ 20% ของเคสทั้งหมด |
| นักเรียนที่ตอบว่า "ถ้ามีเรื่อง จะใช้ระบบนี้" | ≥ 60% |

**ตัวชี้วัดที่ห้ามใช้** (จะทำให้ระบบเสียหาย)

| ห้ามใช้ | เพราะ |
|---|---|
| จำนวนเคสที่ตรวจพบ (ยิ่งมากยิ่งดี) | จะจูงใจให้ตั้งเกณฑ์ต่ำจนครูจมกับเคสปลอม |
| จำนวนเคสในห้องแต่ละครู | จะทำให้ครูเลี่ยงการบันทึกเคส |
| อัตราการเช็กอิน 100% | จะทำให้เกิดการกดผ่านหมู่ ข้อมูลไร้ค่า |

> ตัวชี้วัดที่สำคัญที่สุดของระบบนี้ไม่ใช่ **"ตรวจพบกี่คน"** แต่คือ **"ช่วยได้ทันกี่คน"**

## 5.6 การแก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| `EADDRINUSE` ตอนเริ่มเซิร์ฟเวอร์ | มีเซิร์ฟเวอร์เดิมทำงานอยู่ | ปิดโปรเซสเดิม หรือเปลี่ยน `PORT` |
| ผู้ใช้หลุดออกจากระบบทุกครั้งที่ restart | ไม่ได้ตั้ง `JWT_SECRET` | ตั้งใน `server/.env` |
| ครูที่ปรึกษาไม่เห็นเคสของห้องตัวเอง | ยังไม่ได้กำหนดครูที่ปรึกษาให้ห้อง | เมนูผู้ดูแลระบบ → ห้องเรียน |
| เคสระดับ 3–4 ไม่มีผู้รับผิดชอบ | ยังไม่มีบัญชีบทบาท `counselor` | สร้างบัญชีครูแนะแนว |
| นักเรียนล็อกอินไม่ได้ | กรอกผิดเกิน 8 ครั้ง บัญชีถูกล็อก 15 นาที | รอ หรือให้ผู้ดูแลตั้งรหัสผ่านใหม่ |
| เช็กอินเสร็จแล้วไม่มีอะไรเกิดขึ้น | เป็นระดับ 1 ซึ่งถูกต้อง — ไม่เปิดเคส | ดูหน้าภาพรวมเพื่อยืนยันว่าข้อมูลเข้าระบบแล้ว |

## 5.7 การอัปเกรดกฎ

เมื่อโรงเรียนพบว่าเกณฑ์ใดไม่เหมาะกับบริบทของตน:

1. แก้ที่ `server/src/engine/triage.js`
2. **ขึ้นเวอร์ชัน** ที่ `server/src/engine/version.js` (เช่น `rules-1.1.0`)
3. เพิ่ม/แก้เทสต์ที่ `server/test/engine.test.js`
4. รัน `npm test` ให้ผ่านทั้งหมด
5. บันทึกเหตุผลของการเปลี่ยนแปลงไว้ในเอกสารของโรงเรียน

เคสเก่ายังคงบันทึกไว้ว่าใช้กฎเวอร์ชันใด จึงตรวจสอบย้อนหลังได้เสมอ
**อย่าแก้กฎโดยไม่ขึ้นเวอร์ชัน** เพราะจะทำให้อธิบายเคสเก่าไม่ได้
