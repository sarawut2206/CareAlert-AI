# 7. มาตรฐานสากลและการใช้งานบนมือถือ

เอกสารนี้ตอบสองคำถาม: **"ระบบนี้อ้างมาตรฐานอะไรได้บ้าง"** (พร้อมหลักฐานว่าทำจริงตรงไหนในโค้ด)
และ **"จะใช้เป็นแอปบนมือถือได้อย่างไร"**

หลักการเดียวกับทั้งโครงการ: อ้างเฉพาะสิ่งที่ตรวจสอบได้ —
"สอดคล้องกับแนวทาง X" ไม่เท่ากับ "ได้รับการรับรองจาก X" และเอกสารนี้ไม่อ้างอย่างหลัง

---

## 7.1 แอปบนมือถือ (PWA — Progressive Web App)

ระบบเป็น **Progressive Web App เต็มรูปแบบ** ซึ่งเป็นมาตรฐานเปิดของ W3C
ที่องค์กรระดับโลก (Starbucks, X/Twitter, Uber) ใช้แทนแอปเนทีฟ:

| ความสามารถ | ทำงานอย่างไร | ไฟล์ |
|---|---|---|
| ติดตั้งลงหน้าจอโฮมได้ | Web App Manifest (ชื่อ ไอคอน สี ภาษาไทย) | `web/public/manifest.webmanifest` |
| เปิดเต็มจอเหมือนแอป | `display: standalone` + iOS meta tags | `web/index.html` |
| **หน้าสายด่วนใช้ได้แม้ออฟไลน์** | Service Worker cache ข้อมูล `/api/meta/help` | `web/public/sw.js` |
| เปิดเร็วแม้เน็ตช้า | cache ไฟล์นิ่งแบบ stale-while-revalidate | `web/public/sw.js` |
| ทางลัด "ขอความช่วยเหลือ" กดค้างที่ไอคอน | manifest shortcuts → เปิด `?help=1` | `manifest.webmanifest` |
| ชวนติดตั้งในจังหวะเหมาะสม | `beforeinstallprompt` (Android) / คำแนะนำ (iOS) | `web/src/components/InstallPrompt.tsx` |
| รองรับจอมีรอยบาก | `env(safe-area-inset-*)` | `web/src/styles.css` |

### กติกาความปลอดภัยของ Service Worker (สำคัญกว่าความเร็ว)

1. **cache ข้อมูลสายด่วนได้อย่างเดียว** — ข้อมูลเคส/คิวของครู **ห้าม cache เด็ดขาด**
   เพราะครูที่เห็นคิวเก่าค้างอาจพลาดเคสระดับ 4 ที่เพิ่งเข้ามา
2. **ไม่แตะคำขอเขียนข้อมูล** (POST/PUT/DELETE) ทุกกรณี
3. หน้าแอปใช้ network-first — ของสดมาก่อน ออฟไลน์ค่อยใช้ของเก็บไว้

### วิธีติดตั้งบนมือถือ (บอกนักเรียนแบบนี้ได้เลย)

**Android (Chrome):** เปิดเว็บ → จะมีปุ่ม "ติดตั้ง" ขึ้นเอง หรือเมนู ⋮ → "ติดตั้งแอป"

**iPhone/iPad (Safari):** เปิดเว็บ → ปุ่มแชร์ (สี่เหลี่ยมมีลูกศรขึ้น) → "เพิ่มลงไปยังหน้าจอโฮม"

### เส้นทางขึ้น App Store (ถ้าต้องการในอนาคต — ไม่จำเป็นสำหรับการใช้งานจริง)

| ช่องทาง | วิธี | ค่าใช้จ่าย |
|---|---|---|
| **Google Play** | TWA (Trusted Web Activity) ผ่านเครื่องมือ Bubblewrap — ห่อ PWA เดิมโดยไม่ต้องเขียนโค้ดใหม่ | บัญชีนักพัฒนา $25 ครั้งเดียว |
| **Apple App Store** | ต้องห่อด้วย Capacitor/WKWebView + มี Mac สำหรับ build | บัญชีนักพัฒนา $99/ปี |

> ข้อแนะนำตรง ๆ: สำหรับโรงเรียน **PWA เพียงพอแล้ว** — ได้ไอคอน เต็มจอ ออฟไลน์
> โดยไม่มีค่าใช้จ่ายรายปี ไม่ต้องรอรีวิว และอัปเดตถึงผู้ใช้ทันทีที่ deploy
> ขึ้น store ค่อยทำเมื่อมีเหตุผลจริง เช่น ข้อกำหนดจัดซื้อของหน่วยงาน

## 7.2 การเข้าถึง — อิง WCAG 2.1 (W3C)

| เกณฑ์ WCAG | สถานะ | หลักฐานในโค้ด |
|---|---|---|
| 1.4.3 คอนทราสต์ของสีข้อความ | ✅ | จานสีใน `styles.css` — ข้อความหลัก #17222f บนพื้นขาว (>12:1) |
| 2.4.7 เห็นตำแหน่งโฟกัสเสมอ | ✅ | `:focus-visible` เส้นขอบส้ม 3px |
| 2.3.3 ปิดแอนิเมชันได้ | ✅ | `prefers-reduced-motion: reduce` |
| 2.5.5 ปุ่มใหญ่พอสำหรับนิ้ว (≥44px) | ✅ | ปุ่มตัวเลือก `.choice` สูง ~52px |
| 3.1.1 ระบุภาษาของหน้า | ✅ | `<html lang="th">` + `lang` ใน manifest |
| 1.3.1 โครงสร้างสื่อความหมาย | ✅ บางส่วน | label ผูกกับ input, `aria-modal`, `role="dialog"` |
| 4.1.2 ชื่อ/บทบาทของ控件 | 🔲 ต้อง audit | ควรตรวจด้วย screen reader จริง (NVDA/VoiceOver) |
| 1.1.1 ข้อความแทนรูปภาพ | ✅ | `alt` บนโลโก้, อีโมจิประดับติด `aria-hidden` |

**ยังไม่อ้างว่า "ผ่าน WCAG 2.1 AA"** — อ้างได้เมื่อผ่านการ audit ด้วยเครื่องมือ (axe, Lighthouse)
และผู้ใช้ screen reader จริงแล้วเท่านั้น รายการข้างต้นคือสิ่งที่ทำแล้วและตรวจย้อนได้

## 7.3 ความปลอดภัย — อิงแนวทาง OWASP

| หมวด (OWASP ASVS) | สิ่งที่ทำ | ไฟล์ |
|---|---|---|
| V2 การยืนยันตัวตน | scrypt + salt, ล็อกบัญชีเมื่อผิด 8 ครั้ง, บังคับเปลี่ยนรหัสชั่วคราว | `server/src/lib/crypto.js`, `routes/auth.js` |
| V3 Session | JWT HS256 หมดอายุ 8 ชม., ตรวจ signature แบบ timing-safe | `lib/crypto.js` |
| V4 การควบคุมสิทธิ์ | ตรวจ role ทุกเส้นทางฝั่งเซิร์ฟเวอร์ ครูเห็นเฉพาะห้องตัวเอง | `middleware/auth.js` |
| V5 ตรวจสอบ input | ตัวตรวจชนิด/ช่วง/ความยาวทุกฟิลด์ | `lib/http.js` |
| V7 บันทึกเหตุการณ์ | audit log ครอบคลุมการอ่านข้อมูลนักเรียน | `lib/audit.js` |
| V13 API | rate limiting, ไม่มี CORS ใน production | `middleware/ratelimit.js` |
| V14 ค่าตั้งต้น | CSP, nosniff, X-Frame-Options DENY, Referrer-Policy | `web/index.html`, `server/src/index.js` |

## 7.4 ข้อมูลส่วนบุคคล — PDPA ไทย เทียบหลักสากล (GDPR)

| หลักการ | GDPR | ในระบบนี้ |
|---|---|---|
| เก็บเท่าที่จำเป็น | Data minimization (Art. 5) | ไม่เก็บแชต/ตำแหน่ง/ชีวมิติ — ดู [docs/04](04-จริยธรรมและ-PDPA.md) |
| จำกัดเวลาเก็บ | Storage limitation | นโยบาย retention + เครื่องมือลบโดยผู้ดูแล |
| โปร่งใสต่อเจ้าของข้อมูล | Transparency (Art. 12) | เอกสารความยินยอมภาษาเด็กอ่านเข้าใจ + บอกข้อยกเว้นล่วงหน้า |
| สิทธิ์เข้าถึง/ลบ | Art. 15, 17 | ช่องทางผ่านครูแนะแนว มีข้อยกเว้นเรื่องคุ้มครองเด็ก |
| บันทึกการเข้าถึง | Accountability (Art. 5.2) | audit log + คำแนะนำสุ่มตรวจรายภาคเรียน |

## 7.5 กรอบวิชาการสากลที่ระบบวางตัวสอดคล้อง

| กรอบ | องค์กร | จุดที่สอดคล้อง |
|---|---|---|
| mhGAP | WHO | คัดกรอง ≠ วินิจฉัย, ประเมินหลายมิติ, ส่งต่อเมื่อเกินขอบเขต |
| GLAD-PC | AAP | Screen → Review → Refer → Follow-up |
| Behavioral Threat Assessment | U.S. Secret Service NTAC | ช่องทางรับแจ้ง + ทีมมนุษย์ประเมิน + ไม่ทำโปรไฟล์ |
| School Connectedness | CDC | มิติปัจจัยปกป้อง + โมดูลทักษะชีวิต |
| Child Safeguarding | UNICEF | human-in-the-loop, ไม่ตีตรา, สายด่วนเข้าถึงได้เสมอ (แม้ออฟไลน์) |

## 7.6 สิ่งที่อยู่ในแผนแต่ยังไม่ทำ (พูดตรง ๆ)

| รายการ | เหตุผลที่ยังไม่ทำ | เมื่อไหร่ควรทำ |
|---|---|---|
| ภาษาอังกฤษ (i18n) | ข้อความทั้งระบบออกแบบเป็นภาษาไทยสำหรับเด็กไทย การแปลต้องผ่านผู้เชี่ยวชาญด้านภาษาที่เด็กใช้จริง ไม่ใช่แปลตรงตัว | เมื่อมีโรงเรียนนานาชาติ/ต่างประเทศต้องการใช้ |
| Lighthouse/axe audit อัตโนมัติใน CI | ยังไม่มี CI (token ไม่มี workflow scope) | เมื่อเปิด GitHub Actions ได้ |
| การแจ้งเตือนแบบ push | push ต้องมี backend ที่เปิดตลอด + ต้องคิดเรื่องความเป็นส่วนตัวของ noti บนจอล็อกให้จบก่อน (ห้ามมีเนื้อหาอ่อนไหวเด้งบนจอ) | หลังนำร่องจริง |
| ขึ้น Google Play (TWA) | มีค่าบัญชีนักพัฒนาและงานดูแลเพิ่ม โดยที่ PWA ให้ประสบการณ์เท่ากันแล้ว | เมื่อมีข้อกำหนดจัดซื้อบังคับ |
